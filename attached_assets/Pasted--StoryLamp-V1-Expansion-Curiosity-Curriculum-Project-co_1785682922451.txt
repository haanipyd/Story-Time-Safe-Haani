# StoryLamp V1 Expansion — Curiosity Curriculum

## Project context

StoryLamp is an existing mobile application for Indian parents and children. The current application already includes:

* Expo 54
* React Native 0.81
* Expo Router
* React 19
* React Query
* Node.js 24
* Express 5
* TypeScript
* PostgreSQL
* Drizzle ORM
* Passwordless phone OTP authentication through MSG91
* JWT access tokens and refresh tokens
* Razorpay subscriptions
* Meta Conversions API
* Audio story catalog
* Favorites
* Listening history
* Continue listening
* Listening streaks
* Interactive branching stories
* Flashcards
* Multiple child profiles
* Push notifications
* Daily picks
* Parent feedback
* Admin panel
* EAS Android production build

The production API is currently deployed at:

`story-time-safe--haanipyd.replit.app`

Do not rebuild the project from scratch.

First inspect the complete existing monorepo, database schema, API routes, authentication flow, mobile navigation, admin panel, subscription logic and existing content models.

Preserve all working features unless a database migration or interface change is clearly required.

Before implementing, create a concise internal implementation plan showing:

1. Existing components that can be reused
2. Database migrations required
3. New API endpoints required
4. New mobile routes required
5. New admin features required
6. Existing features that need modification
7. Risks to current authentication, subscriptions and production data

Do not delete or rename existing production tables, routes or fields without creating a backward-compatible migration.

---

# 1. Product vision

StoryLamp should not be positioned only as an audio-story application.

The expanded product is:

> A personalized vernacular Curiosity Curriculum that helps children become more curious, aware, expressive, imaginative and knowledgeable through stories, picture learning, puzzles, conversations and real-world activities.

The central parent promise is:

> Never wonder what your child should discover next.

StoryLamp should give parents a structured journey rather than an unorganized content library.

Audio stories remain an important part of the product, but the complete experience should contain:

* Audio stories
* Illustrated stories
* Words and names
* Picture learning
* General knowledge
* Puzzles
* Thinking activities
* Values and emotional learning
* Parent-child conversations
* Real-world activities
* Parent guidance
* Progress summaries
* Personalized recommendations

The application must feel useful to the parent even when the child is not directly using the phone.

---

# 2. Initial target customer

Build the guided Curiosity Journey primarily for:

* Parents of children aged 3–6
* Malayalam-speaking families
* Parents who already buy books, toys, worksheets or educational content
* Parents who want their children to become curious, expressive and aware
* Parents who want meaningful learning without excessive passive screen time

The existing story library can continue supporting children aged 2–10.

Use the following initial age bands:

* 2–3 years
* 3–4 years
* 5–6 years
* 7–8 years
* 9–10 years

The structured V1 Curiosity Curriculum should initially prioritise the 3–4 and 5–6 age bands.

# 3. Core product structure

The primary product structure must be:

```text
Monthly Theme
    ↓
Four Weekly Journeys
    ↓
Multiple connected content experiences
    ↓
Parent feedback and observation
    ↓
Progress summary
    ↓
Personalized next recommendation
```

Each monthly theme should contain four weekly subthemes.

Each weekly journey should ideally contain:

1. One audio or illustrated story
2. One Picture Explorer set
3. One puzzle or thinking activity
4. One parent-child conversation
5. One offline real-world activity
6. One values, behaviour or emotional-learning idea
7. One short parent guidance note
8. One completion and feedback interaction

All these items should be connected around the same topic.

For example:

```text
Monthly theme: My Home, My World

Week 1: Rooms in My Home
Week 2: Objects We Use
Week 3: My Family at Home
Week 4: Keeping Our Home Safe and Clean
```

The child should build connected understanding rather than encounter random, disconnected facts.

# 27. Important implementation instructions

* Extend the existing StoryLamp monorepo.
* Do not create a separate prototype repository.
* Do not replace working authentication.
* Do not replace working subscription logic.
* Do not break the current production API.
* Do not hardcode curriculum content in mobile components.
* Store all content in PostgreSQL.
* Use Drizzle migrations.
* Use TypeScript throughout.
* Reuse current design components where appropriate.
* Reuse the current audio player and story history.
* Keep API contracts backward compatible.
* Add automated validation for new content schemas.
* Add tests for critical journey, entitlement and progress logic.
* Mark generated content as Draft until reviewed.
* Never automatically publish AI-generated content.
* Keep private child observations out of marketing analytics.

After inspecting the codebase, begin with the database and shared content architecture. Then implement one complete end-to-end sample theme before expanding the remaining themes.

The first complete sample theme should be:

> My Home, My World

It should include four weekly journeys and all major content types.

Once that theme works end to end, use the same reusable architecture to add the remaining themes and maximum available content.
